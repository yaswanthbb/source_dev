## Existing save contract and safeguards

- Only existing authenticated account/detail GETs and PATCH `/articles/:id`. No list fetch is needed to edit an article. Account/detail reads use the shared timed/abortable helpers; entry has no mutation, automatic retry, focus or reconnect refetch. Cache keys include actor ID/role and article ID, never a token.
- Strict matching ID, ownership (author or admin), timestamps, body and optional-link validation. Editor props/query data contain only normalized account data and permission-checked article fields, never raw author objects, password hashes, unrelated entity metadata or slugs. Stored article text is needed for editing; unsaved draft text stays out of the query cache.
- Shared fresh account/role and token-session checks, then a complete saved fingerprint including body, owner, title, timestamps and links before one PATCH. Changed saved data stops before writing. The existing backend still regenerates slug for title changes; reader/editor routes remain ID-based.
- PATCH includes title, exact Markdown and both link fields with explicit null clearing. A validated matching acknowledgement and another checked detail/account read must agree before success. Original article ID, authorship and creation date must remain unchanged. No optimistic update, automatic navigation or draft clearing.
- Synchronous busy guard prevents duplicate in-flight saves. Transport/408/5xx/malformed ACK/readback ambiguity pauses saving and preserves local writing; definite field refusals retain the draft without claiming success. Safe error wrappers discard raw Axios request/config/response messages. Failed read-only checks keep saving locked.
- Conflict/recovery checks stage a checked saved version without replacing the draft or silently adopting a new baseline. User can compare escaped checked Markdown and links, then explicitly keep the draft against that baseline or replace the draft. Replacement has a separate native confirmation describing local text loss and sends no write. The next save checks again.
- A successful recovery read cannot cancel an earlier save. The late-request warning stays after explicit version adoption, including when current text matches the checked version. No backend conditional update, atomic identity/fingerprint or exactly-once/cross-tab guarantee is claimed.
- No backend, schema, dependency, migration, provider, progress or terminal-command changes. Shared helper export/abort-signal changes preserve checkpoint 20 behavior.
